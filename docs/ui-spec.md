# envboard 工作台 UI 规范

> 工作台界面的**单一事实来源**：约束、视觉令牌、布局与交互纪律，以及每个决定背后的理由。
> 令牌的机器可读定义在 `core/rs/crates/envboard-web/assets/app.css` 第 ① 区（`:root`），
> 本文件解释"为什么是这些值"；两者不一致时，以 `app.css` 为准并回改本文件。

---

## 1. 约束优先于审美

工作台跑在一个**没有 `unsafe-inline` 的 CSP** 下（见 `core/rs/crates/envboard-web/src/config.rs`
的 `CONTENT_SECURITY_POLICY`）。这条约束决定了四件事，全部不可协商：

| 约束 | 落地形态 |
|---|---|
| 无内联脚本 | 全页只有一个 `<script src="/app.js" defer>`；页面里其余"脚本感"的东西（图标精灵）是 SVG `<symbol>`，不是脚本 |
| 无内联样式 | 三个外置文件；HTML 里零 `style` 属性、零 `<style>` 元素 |
| 无内联事件 | 事件一律 `addEventListener`（`wire()`），零内联事件属性 |
| 图标不引字体、不发请求 | 同文档 SVG 精灵 + `<use href="#i-…">`，`stroke: currentColor`，同一份图标随语境变色 |

**两条实测教训**（都来自 `verify_live_v2.py` 的实机断言，curl 层查不出来）：

1. HTML **注释里也不能写**脚本/样式标签的字面量 —— 断言就是在页面源码里按字面量找它们，
   一条解释性注释曾让「无内联脚本」断言 FAIL。注释里描述这类写法时用文字，不用尖括号。
2. 页面"活着"不等于"样式生效"：验收必须读 `getComputedStyle` 并与令牌对齐，
   只看 HTTP 200 查不出 CSS 没加载。证据记录见 `docs/acceptance/m3-workbench.md`。

## 2. 视觉令牌

明亮主题为默认（`:root`）；深色 token 以注释块保留在 `app.css` 供将来整体切换，
切换方式是给 `<html>` 加 `data-theme="dark"`，不需要改任何组件样式。

### 表面与边框

- **表面三级**：`--bg`（页面）/ `--bg-2`（侧栏、日志栏、页签条）/ `--bg-3`（输入框、代码块），
  卡片用 `--panel`（纯白）抬升于页面浅灰之上。
- **层级靠 1px 边框而不是阴影堆叠**：`--line`（常规）/ `--line-2`（强调）。阴影只用于
  浮层（菜单、toast），冷灰低透明。

### 文本四级灰阶

`--text` / `--text-2` / `--muted` / `--muted-2`，每档都标注了对 `--panel` 的实测对比度
（17.5:1 / 9.4:1 / 5.5:1 / 4.6:1）。**新增文本必须落在已有档位上**，不许引入第五档灰。

### 语义色三件套

每个语义色（ok / warn / bad / purple / cyan）都是「原色 + bg(10%) + border(30%)」三个变量，
徽章、提示、日志行统一用它组装。原色全部达到对白底 5:1 左右的可读对比度。

### 几何

- **间距 4px 基数**：只用 `--space-1…8`，不出现 6px、15px 这类孤立值。
- **圆角五档**：`--radius-xs…xl`，同层级必须一致（列表项用 sm，卡片用 lg，不许混）。

**组件层纪律**：组件规则里**不写十六进制色值**，一律 `var(--token)`；色值字面量只允许
出现在 `app.css` 第 ① 区（含深色注释块）。这样主题切换或调色永远是改一处。

## 3. 布局

Grid 四区：`topbar(52px) / sidebar(260px) / main / logbar`，`body` 锁 `100vh` 且
`overflow: hidden` —— 工作台是应用形态，滚动发生在各区内而不是页面上。
响应式断点 1200 / 900 / 640px：窄屏收侧栏为抽屉、统计卡降为两列/单列、日志栏加高。

## 4. 交互纪律

| 纪律 | 理由 |
|---|---|
| 破坏性操作（删除环境）走**就地二次确认**：动作行原地换成"后果说明 + 确认/取消" | 原生 `confirm()` 阻塞主线程、样式不可控，且与"无内联脚本"约束冲突 |
| 动作按钮进行中**禁用 + 标记**，完成后用快照**对账** | 防双击重复提交；UI 最终以服务端状态为准，不是乐观更新 |
| 异常走**三通道**：行内原因、toast、徽章变色 | 单一通道都会被用户错过；健康原因必须可读（如"被信号 9 杀死"） |
| 日志过滤维度是**事件类型**（请求/响应/连接/运行/异常），不是日志级别 | 实测日志行不带 INFO/WARN 前缀，按级别过滤是个假功能 |
| 日志视图 `aria-live="off"`，跟随开关显式控制自动刷新 | 每秒一次的快照会让读屏器持续重放，属于噪声 |
| `prefers-reduced-motion: reduce` 下关闭过渡与动画 | 前庭敏感用户的基本保障 |

**引导链隔离**：启动序列的每个步骤（绑定事件、视图、筛选、日志、事件流）都过 `step()`
壳 —— 任何一步抛错只记进 `documentElement.dataset.envboardError` 并把
`envboardReady` 置 `"no"`，**数据加载照常继续**。实测教训：一个写错的容器 id 曾让
`renderLogs` 抛空指针并中断整条链，页面停在空壳、ready 永远停在 `"pending"`，
验收只看到"没就绪"看不出坏在哪。`envboardReady === "yes"` 仍然表示"全部步骤零错误跑完"，
这条验收契约没有放松。
