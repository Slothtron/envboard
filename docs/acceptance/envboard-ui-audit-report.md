## 一、颜色系统问题（4 项）

### 1.1 侧边栏与日志栏背景色偏蓝灰，与页面背景色调不统一

| 项目 | 内容 |
|------|------|
| **严重程度** | 🔴 高 |
| **位置** | `.sidebar` / `.logbar` |
| **当前值** | 背景色 `#e9edf4`（偏蓝的冷灰色） |
| **页面背景** | `#f4f6fa`（中性浅灰） |

**问题描述：**

页面背景为中性浅灰色，但侧边栏和日志栏使用偏蓝的冷灰色，两者色调不一致，导致界面看起来有明显"色差"。侧边栏和日志栏显得偏暗偏冷，破坏了整体视觉统一性。

**修复建议：**

统一使用中性灰色系。侧边栏和日志栏背景改为 `#f1f4f9` 或 `#eef1f6`，与页面背景 `#f4f6fa` 保持同一灰度色系，仅在明度上有层次区分。

---

### 1.2 日志内容区域背景透明，文字对比度不足

| 项目 | 内容 |
|------|------|
| **严重程度** | 🔴 高 |
| **位置** | `.log-view` |
| **当前值** | 背景 `transparent`，文字色 `#3d4757` |

**问题描述：**

日志内容区域背景为透明，直接显示在日志栏 `#e9edf4` 的蓝灰背景上。日志文字颜色 `#3d4757` 在蓝灰背景上对比度不足，长时间阅读容易疲劳。且日志区域应该有独立的、更浅的背景色，与日志栏头部形成层次区分。

**修复建议：**

日志内容区域设置独立背景色 `#ffffff` 或 `#f8fafc`，与日志栏头部（灰色）形成对比。文字颜色调整为 `#1e293b` 提高对比度。

---

### 1.3 统计卡片默认激活态无意义

| 项目 | 内容 |
|------|------|
| **严重程度** | 🟡 中 |
| **位置** | `.stat-card.is-active`（第一个卡片） |
| **当前值** | 蓝色背景 `rgba(42,95,232,0.1)` + 蓝色边框 |

**问题描述：**

第一个统计卡片（环境总数）默认带有 `is-active` 类，显示蓝色背景和蓝色边框。但这不是用户点击选择的结果，统计卡片也不是单选组件，默认高亮没有交互语义，会让用户困惑。

**修复建议：**

移除默认的 `is-active` 状态。如果统计卡片支持点击筛选，点击后才显示激活态；如果不支持点击，所有卡片使用统一样式，仅通过图标颜色区分类型。

---

### 1.4 日志分隔线颜色过于突出

| 项目 | 内容 |
|------|------|
| **严重程度** | 🟢 低 |
| **位置** | `.log-line.separator` |
| **当前值** | 紫色/淡紫色背景 |

**问题描述：**

日志中的分隔行（如 `--- envboard: env=beta ... ---`）使用了紫色/淡紫色背景，在整体蓝灰色调的日志区域中过于突出，视觉权重过高，干扰了正常日志内容的阅读。

**修复建议：**

分隔行使用更克制的样式，如浅灰色背景（`#f1f4f9`）+ 灰色文字，或仅使用上下边框线分隔，不需要整行背景色。

## 二、布局与间距问题（3 项）

### 2.1 信息网格无边框分隔，各信息项难以区分

| 项目 | 内容 |
|------|------|
| **严重程度** | 🟡 中 |
| **位置** | `.info-cell`（概览页面信息网格） |
| **当前值** | 背景 `#ffffff`，无边框，无分隔线 |

**问题描述：**

概览页面的信息网格（状态、监听端口、期望、规则绑定等）使用 `.info-cell`，背景为白色、无边框、无分隔线。由于外层详情面板也是白色背景，各个信息项完全"融"在面板中，用户无法直观区分每个信息项的边界，信息层级不清晰。

**修复建议：**

为信息网格添加分隔线（使用 `background: var(--line)` 的 1px 网格间隙），或为每个 `.info-cell` 添加 `border: 1px solid var(--line)` 和圆角，使每个信息项成为独立的卡片。

---

### 2.2 代理命令卡片内边距为 0

| 项目 | 内容 |
|------|------|
| **严重程度** | 🟡 中 |
| **位置** | `.cmd-card` |
| **当前值** | `padding: 0px` |

**问题描述：**

代理命令卡片的 `padding` 为 `0px`，内部的标题、命令文本、复制按钮直接贴在卡片边缘，没有呼吸空间，视觉上显得拥挤且不专业。

**修复建议：**

为 `.cmd-card` 添加合理的内边距，如 `padding: 14px 16px`。命令文本区域可以单独设置 `padding: 10px 12px` 和背景色，与卡片头部形成层次。

---

### 2.3 主内容区上下间距偏小

| 项目 | 内容 |
|------|------|
| **严重程度** | 🟢 低 |
| **位置** | `main` / `.main-content` |

**问题描述：**

主内容区的顶部间距偏小，统计卡片距离顶部栏太近，视觉上显得局促。底部与日志栏之间的间距也需要确认是否足够。

**修复建议：**

主内容区设置 `padding: 20px 24px`，确保与顶部栏和日志栏都有足够的呼吸空间。统计卡片与详情面板之间保持 `16px` 间距。

## 三、组件样式问题（5 项）

### 3.1 按钮高度不统一

| 项目 | 内容 |
|------|------|
| **严重程度** | 🔴 高 |
| **位置** | `button` / `.btn` / `.icon-btn` / `.seg-btn` |
| **当前值** | 存在 `24px` / `26px` / `30px` 多种高度 |

**问题描述：**

页面中按钮高度不统一：

- 分段控件（`.seg-btn`）：`26px`
- 普通按钮（`.btn`）：`30px`、`26px`、`24px` 多种
- 图标按钮（`.icon-btn`）：`30px` 和 `26px` 两种

按钮高度混乱导致界面视觉不整齐，同一行内的按钮高度不一致时尤其明显。

**修复建议：**

建立统一的按钮尺寸规范：

| 级别 | 高度 | 上下 padding | 左右 padding | 适用场景 |
|------|------|-------------|-------------|---------|
| 主按钮（primary） | 32px | 6px | 14px | 主要操作（启动、创建、保存） |
| 次按钮（default） | 30px | 5px | 12px | 次要操作（重启、编辑、复制） |
| 小按钮（sm） | 26px | 3px | 10px | 标签、筛选、行内操作 |
| 图标按钮 | 与对应级别一致 | - | - | 纯图标操作 |

同一操作区域内的按钮必须使用同一高度规格。

---

### 3.2 主按钮上下 padding 为 0

| 项目 | 内容 |
|------|------|
| **严重程度** | 🔴 高 |
| **位置** | `.btn.primary` |
| **当前值** | `padding: 0px 12px` |

**问题描述：**

主按钮的 `padding` 为 `0px 12px`，上下没有内边距，按钮高度完全由文字内容和行高撑开。这导致按钮高度不可控，不同文字内容或字体渲染差异可能导致按钮高度变化，且点击热区偏小。

**修复建议：**

为主按钮设置明确的高度或上下 padding，如 `height: 32px` 或 `padding: 6px 14px`，确保按钮高度稳定且点击热区足够。

---

### 3.3 顶部导航分段控件高度过小

| 项目 | 内容 |
|------|------|
| **严重程度** | 🟡 中 |
| **位置** | `.seg-btn`（环境/规则库/跨环境对比） |
| **当前值** | 高度 `26px`，顶部栏高度 `52px` |

**问题描述：**

顶部栏高度为 `52px`，但其中的分段导航控件高度仅 `26px`，在顶部栏中显得过小，视觉权重不足。且点击热区偏小（26px 高度低于推荐的 44px 可点击区域，虽然桌面端可接受但偏小）。

**修复建议：**

分段控件高度调整为 `30px` 或 `32px`，与顶部栏中的其他按钮（刷新按钮 30px）保持一致，提升视觉平衡和点击体验。

---

### 3.4 搜索框与相邻按钮高度不一致

| 项目 | 内容 |
|------|------|
| **严重程度** | 🟡 中 |
| **位置** | `.search-box`（侧边栏搜索框） |
| **当前值** | 搜索框 `30px`，新建按钮 `26px` |

**问题描述：**

侧边栏搜索框高度为 `30px`，但旁边的新建按钮（+）为 `26px`，同一行内的输入框和按钮高度不一致，视觉上不整齐。

**修复建议：**

统一搜索框和相邻按钮的高度，建议都使用 `30px`。搜索框 `height: 30px`，按钮也设置 `height: 30px`。

---

### 3.5 边框宽度使用 0.8px

| 项目 | 内容 |
|------|------|
| **严重程度** | 🟢 低 |
| **位置** | 全局 border（顶部栏、侧边栏、卡片、按钮等） |
| **当前值** | `0.8px` |

**问题描述：**

页面中大量使用 `0.8px` 的边框宽度。在 1x 分辨率的非高清屏幕上，0.8px 可能被渲染为 1px 或显示模糊，边框视觉效果不一致。

**修复建议：**

统一使用 `1px` 边框宽度，确保在所有屏幕上渲染一致。如果需要更细的视觉效果，可以通过降低边框颜色的不透明度来实现，而不是使用小于 1px 的宽度。

## 四、日志区域问题（3 项）

### 4.1 日志行高偏小

| 项目 | 内容 |
|------|------|
| **严重程度** | 🔴 高 |
| **位置** | `.log-line` |
| **当前值** | 行高 `19px`，字体 `11.5px`，行高比约 1.65 |

**问题描述：**

日志行高度为 `19px`，字体大小为 `11.5px`，行高比约 1.65。对于等宽字体的日志阅读来说，行高偏小，多行日志之间显得拥挤，长时间阅读容易串行。且日志内容可能包含较长的 URL 和请求信息，足够的行高有助于提升可读性。

**修复建议：**

日志行高调整为 `22px` 或 `24px`，行高比达到 1.9-2.1，提升日志可读性。或者设置 `line-height: 1.8` 让行高随字体大小自动计算。

---

### 4.2 日志级别标签全圆角过于突出

| 项目 | 内容 |
|------|------|
| **严重程度** | 🟡 中 |
| **位置** | `.log-line .badge`（REQ/RES/CONN/RUN/ERR 等） |
| **当前值** | `border-radius: 999px` 全圆角 + 背景色 |

**问题描述：**

日志中的级别标签使用了 `border-radius: 999px` 的全圆角徽章样式，带有背景色。在密集的日志列表中，这些全圆角徽章视觉权重过高，吸引了过多注意力，而日志的核心内容（URL、状态码等）反而不够突出。

**修复建议：**

日志级别标签改为更轻量的样式：

- **方案 A（推荐）：** 仅使用文字颜色区分级别，不加背景色和边框
- **方案 B：** 使用小圆角（`border-radius: 3px`）+ 极淡的背景色，降低视觉权重
- 标签宽度固定（如 `40px`），文字右对齐，使日志内容左对齐整齐

---

### 4.3 日志区域上下内边距不对称

| 项目 | 内容 |
|------|------|
| **严重程度** | 🟢 低 |
| **位置** | `.log-view` |
| **当前值** | `padding: 8px 16px 12px`（上 8px / 下 12px） |

**问题描述：**

日志内容区域的上下内边距不对称，上边距 8px、下边距 12px。虽然这可能是为了给滚动条留出空间，但视觉上不够平衡。

**修复建议：**

统一上下内边距为 `10px 16px`，保持视觉平衡。如果需要为滚动条预留空间，可以通过调整滚动条样式或右侧内边距来实现。

## 五、排版与字体问题（3 项）

### 5.1 整体字体偏小

| 项目 | 内容 |
|------|------|
| **严重程度** | 🟡 中 |
| **位置** | 全局 |
| **当前值** | 正文 `13.5px`，按钮/标签页 `12.5px`，辅助文字 `11-12px` |

**问题描述：**

页面正文字体大小为 `13.5px`，按钮和标签页文字为 `12.5px`，辅助文字为 `11-12px`。整体字体偏小，对于管理后台类工具，长时间使用容易造成视觉疲劳。常规后台系统的正文字号通常为 `14px`。

**修复建议：**

调整字体层级：

| 层级 | 字号 | 适用场景 |
|------|------|---------|
| 正文/表格内容 | 14px | 主要内容、表格数据 |
| 按钮/标签页 | 13px | 操作按钮、标签导航 |
| 辅助文字/标签 | 12px | 说明文字、状态标签、时间戳 |
| 日志等密集内容 | 11.5-12px | 日志行、代码片段 |

行高统一为 `1.5-1.6`。

---

### 5.2 标签页选中态字重区分度不够

| 项目 | 内容 |
|------|------|
| **严重程度** | 🟢 低 |
| **位置** | `.tab` / `[role=tab]`（概览/配置/规则） |
| **当前值** | 选中态和未选中态字重均为 `500` |

**问题描述：**

标签页选中态和未选中态的字重都是 `500`，仅通过颜色（蓝色 vs 灰色）和底部边框区分。在浅色背景下，灰色文字和蓝色文字的区分度尚可，但增加字重差异可以进一步提升选中态的视觉权重。

**修复建议：**

选中态标签页字重调整为 `600`，未选中态保持 `400` 或 `500`，通过字重差异增强选中态的视觉突出度。

---

### 5.3 环境名称与状态徽章基线对齐不完美

| 项目 | 内容 |
|------|------|
| **严重程度** | 🟢 低 |
| **位置** | 详情面板标题（环境名称 + 状态徽章） |

**问题描述：**

详情面板标题中，环境名称（beta）和状态徽章（stopped）在同一行显示，但由于徽章有上下 padding 和不同的行高，两者的文字基线可能没有完美对齐，视觉上有轻微的错位感。

**修复建议：**

标题容器使用 `display: flex; align-items: center;` 确保环境名称和状态徽章垂直居中对齐。徽章设置 `align-self: center`，或调整徽章的 `line-height` 与标题文字一致。

## 六、修复优先级建议

6. **日志行高调整** — 影响日志阅读体验

4. 搜索框与按钮高度统一
5. 日志级别标签样式轻量化

### 第三梯队（后续优化，细节打磨）

1. 日志分隔线颜色调整
