## 3. 实机端到端

真起一个 `mitmweb`（默认代理 `127.0.0.1:18080`、Web `127.0.0.1:18081`、独立 confdir；
两者都可用 `PROXY_PORT` / `WEB_PORT` 覆盖），用 curl 打真实 HTTP 接口，
断言状态码、响应体与磁盘状态。

> 这一节是 **curl 视角**。它能证明"服务端返回了什么"，**证明不了"浏览器能不能跑起来"** ——
> 内联 `<script>` 被 CSP 拒绝那次，这里 29 条全绿，而 Dashboard 在真浏览器里完全是死的。
> 前端行为必须另有真浏览器验收；本节新增的三条资源断言就是那次事故留下的门禁。

### 3.1 真浏览器验收（Chrome）

用 browser-skill 挂真 Chromium 跑了一遍完整用户流程：

| 步骤 | 结果 |
|---|---|
| 打开 `/envboard/` | JS 正常执行，状态栏 `active: local` / `dns: 192.0.2.53`（系统 DNS 被动态读到） |
| 点「+ 新建」，填 `prod` + `192.0.2.53`，保存 | `POST /api/environments` → **201**，列表出现 `prod` |
| 点「切换到此环境」 | `PUT /api/active` → **200**，状态栏变 `active: prod` |
| 填 `example.com`，点「对比所有环境」 | `POST /api/resolve` → **200**，映射表 4 行（`local`×2 + `prod`×2，各 2 条 A 记录） |
| 填 `10.0.0.53:53` 保存 | `POST /api/environments` → **400**，环境未被创建，错误以 toast 呈现 |

规则文件那一轮，同一条路径又跑了一遍（输入刻意弄脏）：

| 步骤 | 结果 |
|---|---|
| 「规则文件」面板粘贴 6 行混合内容，规则名填 `demo`，点「导入并规范化」 | 报告 `accepted=6 over 4 ip，skipped=1，conflicts=1` |
| — 其中含 `beta.example.com 10.0.0.2`（反序）、缩进行带行尾注释、`not-an-ip.example.com`（非法）、`dup.example.com` 两次不同 ip | 非法行被忽略并列出 `L5 too-few-tokens not-an-ip.example.com`；冲突被列为 `dup.example.com 10.0.0.4 → 10.0.0.5` |
| 绑定下拉选 `demo` | 环境列表变 `local ● active · rules: demo`，表格变 `demo \| 6 \| 4 \| local` |
| 解析 `api.example.com, dup.example.com, spaced.example.com` | 映射表 3 行**全部 `static`**，分别是 `10.0.0.1` / **`10.0.0.5`** / `10.0.0.3` —— 冲突真的按"后出现者胜"生效了，且三条都没走 DNS |

### 这几条断言分别锁住了什么

| 断言 | 锁住的契约 |
|---|---|
| `dashboard HTML served` / `xsrf cookie issued` | Dashboard 真的挂在 mitmweb 上，且走的是宿主自己的 XSRF 机制 |
| `rejects ip:port with field path` | `10.0.0.53:53` 被拒，且错误里带得出 `environment.dns_servers[0]` 这样的字段路径 |
| `delete inactive env succeeds (XSRF on empty body)` | tornado 的 XSRF 对**空 body 的 DELETE** 同样生效 —— 这是实机踩过的坑 |
| `refuses deleting active env` | 409，不允许把当前激活环境删掉 |
| `bad limit is a 400, not a 500` | 坏查询参数是**客户端错误**，不是 500 |
| `reverse endpoint removed (404)` | 反向解析这条路是**真的删干净了**，不是只从文档里删掉 |
| `resolve across all environments` | 核心场景：同一批域名分别向每套环境的 DNS 各查一次 |
| `write without XSRF -> 403` / `unauthenticated read -> 403` | 写接口与读接口都受宿主鉴权保护 |
| `state file mode 0600` | 状态文件权限收紧 |
| `rules import accepted all valid hosts` / `ignores invalid line` / `conflict keeps last` | 一次导入里同时验证：多 host 共用 ip、非法行忽略、冲突后出现者胜 |
| `normalized file is ip-first` / `drops comments` | 落盘的是**规范化**结果，不是原文转存 |
| `static_from names the rules file` | 规则命中会标明来源 `rules:<name>`，不是一笔糊涂账 |
| `env inline hosts beat the rules file` | 优先级 inline > rules > DNS 真的生效 |
| `refuses deleting a bound rules file` | 409：绑定中的规则文件不能删，否则环境静默失去覆盖 |
| `dashboard has no inline <script>` / `references external app.js` | 内联脚本会被 mitmweb 的 CSP 拒绝执行 —— 这条是真浏览器才发现的 |
| `app.js served as javascript` | 外部资源以同源 `application/javascript` 可取回 |
| `unknown asset -> 404` | 资源白名单挡掉路径穿越与非白名单文件 |
