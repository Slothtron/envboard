# envboard 工作台 UI 升级方案

> **审计对象**：`http://127.0.0.1:8900/`（envboard v2，M3 工作台，core = mitmproxy 12.2.3）
> **证据来源**：运行时抓取 `index.html` / `app.css` / `app.js`（与 WSL 源
> `~/workspace/plugins/packages/envboard/core/rs/crates/envboard-web/assets/` 一致）；
> 实调 `/api/status`、`/api/environments`、`/api/rules`、`/api/compare`、
> `/api/environments/:name`（GET/PATCH）、`/api/rules/:name`；
> 对照 `docs/acceptance/m3-workbench.md`。v2 设计中的相关要求（如实写明暴露面、
> 重分配需提示同步客户端配置、代理命令可复制等）均已在本文引用处以引文形式自包含给出。
> **审计时间**：2026-09-16。
> **方法说明**：本机无 Playwright/Puppeteer，未做像素级截图；布局结论由 CSS 与 DOM 推导，
> 需真机复核的项已在本文件 §8 标注。
> **落地状态**：本方案已于 2026-09-16 实施完成，改动与验收记录见 `CHANGELOG.md`
> 与 `docs/acceptance/` 目录；升级后的界面规范见 `docs/ui-spec.md`（浓缩版）与
> `docs/design/ui-spec-full.md`（全量版）。

## 0. 结论速览

1. 当前 UI 是**单页、零导航、四卡片栅格**的运维面板。**功能完整度达标、交互成熟度不足**：
   M3 定义的能力（CRUD / 启停 / 规则导入 / 日志尾 / 跨环境对比 / SSE）全部落地，
   但 UI 只覆盖后端 API 的 **9/13** 个端点。
2. 最高优先级不是"做新功能"，而是**补齐三类缺口**：
   ① 破坏性操作无护栏（删除无确认、重分配端口不提示后果）；
   ② 关键可复制资产（`proxy_command`）不可复制；
   ③ 状态语义单靠颜色 + 原生 `title` 表达。
3. 建议按 **M5-a（护栏与语义）→ M5-b（详情与能力对齐）→ M5-c（结构与规模化）** 三段推进，
   每段都保持"零构建链 + `include_str!` 内嵌 + 严格 CSP"的既有约束。

| 指标 | 当前 | M5 目标 |
|---|---|---|
| API 端点 UI 覆盖率 | 9 / 13（69%） | 13 / 13 |
| 破坏性操作带确认 | 0 / 2 | 2 / 2 |
| 状态可视化通道（颜色之外） | 1（原生 `title` 悬浮） | ≥ 2（文本 + 图标/建议动作） |
| 表格可定位性（排序 / 筛选 / 搜索） | 无 | 三选二 |
| 窄屏可用性（< 720px） | 未处理（表格横向溢出） | 全部功能可达 |
| 前端资产文件数 | 3（html / css / js） | 3（不变） |

## 1. 现状梳理

### 1.1 页面布局

单个文档流，无路由、无视图切换：

| 区块 | 位置 | 说明 |
|---|---|---|
| 顶栏 | `index.html:16-25`、`app.css:26-34` | 品牌 + 副标题 + 两个状态 pill；渐变背景、底部 1px 分隔线 |
| 主区 `main` | `app.css:57` | `max-width: 1180px` 居中，padding `18px 20px 40px` |
| 环境表面板 | `index.html:28-46` | 全宽 panel，7 列表格，独立占据首屏主位 |
| 四卡片栅格 | `index.html:48-88`、`app.css:99` | `grid-template-columns: repeat(auto-fit, minmax(320px, 1fr))`，`align-items: start` |
| 页脚 | `index.html:91-93`、`app.css:137` | 居中一行说明文字 |

**布局性质**：纵向堆叠 + 自适应卡片栅格。
宽度 ≥ 1180px 时四卡片一行；768–1180px 两行 2×2；< 700px 单列。
**没有粘性元素、没有侧栏、没有滚动容器。**

### 1.2 导航结构

**没有导航。** 无侧栏、无 Tab、无面包屑、无锚点、无滚动高亮，页面定位完全依赖 `h2` 标题与滚动。

顶栏两个 pill 是当前唯一的"全局态"表达（`app.js:184-190`）：

- `core-pill` → `core: mitmproxy 12.2.3`
- `conn-pill` → `真实改写已启用` / `仅监听（不改写）`

值得注意的是，`conn-pill` **同时承载了两个正交维度**：能力（`capabilities.rewrite_upstream`）
与 SSE 连接状态。SSE 断线时它被改写为"事件流断开（界面仍在轮询）"（`app.js:331-338`）。
一个节点表达两件事，是后续语义混乱的来源。

### 1.3 组件体系

| 组件 | 定义位置 | 变体 | 成熟度 |
|---|---|---|---|
| pill / 状态徽章 | `app.css:42-55` | default / ok / warn / bad | 可用，但语义与颜色映射不完整 |
| panel + panel-head | `app.css:59-73` | — | 可用 |
| 数据表格 | `app.css:75-78` | — | 基础；无排序、无筛选、无空状态组件 |
| button | `app.css:84-96` | default / primary / ghost / danger | 缺 loading 与 disabled 态 |
| form | `app.css:101-112` | grid / inline | 可用；无校验反馈组件 |
| list（规则项） | `app.css:120-121` | — | 简陋（仅名字 + 删除） |
| logs（终端） | `app.css:123-135` | — | 只读；无跟随 / 过滤 / 导出 |
| toast | `app.css:139-152` | default / bad | 唯一的用户反馈通道 |
| result row（对比结果） | `app.css:116-118` | covered / uncovered | 一次性，无历史 |

**缺失的基础组件**：Modal / 确认框、Dropdown / 菜单、Tabs、Tooltip（现用原生 `title`）、
Icon（当前全部是纯文本按钮）、Empty state（仅一行 `td.empty` 文本）、Skeleton / Loading、
Pagination、复制按钮。

### 1.4 信息层级

三层结构：顶栏（全局态）→ 面板标题 `h2`（14px / 600）→ 表格与表单内容。

**问题一：层级与任务顺序不一致。**

| 页面顺序 | 使用顺序（README 快速开始 + v2 设计的任务顺序要求） |
|---|---|
| 1 环境表 | 1 导入规则 |
| 2 新建环境 | 2 建环境并绑规则 |
| 3 跨环境对比 | 3 启停与验证 |
| 4 **规则库** | 4 对比 |
| 5 实例日志 | 5 看日志 |

即：**流程第一步要用的「规则库」排在页面第四位**，且被首屏最高权重的环境表挤到下方。
环境数为 0 时首屏只有一句"还没有环境。用下面的「新建环境」加一个。"（`app.js:128`），
而真正该做的第一步（导入规则）在更下面。

**问题二：环境行内部信息过载。**
一行 7 列 + 5~6 个操作按钮（启动 / 停止 / 重启 / 日志 / 删除，端口冲突时再加"重分配端口"，
`app.js:149-178`）。最高交互密度落在表格单元格里，且破坏性操作（删除）与常规操作（启动）
在静态视觉上几乎无差别 —— `.danger` 只在 hover 时才变色（`app.css:96`）。

### 1.5 视觉风格

Design token 现状（`app.css:3-15`）：

- 9 个语义色变量 + 1 个 mono 字体栈
- **没有间距 / 圆角 / 字号 / 阴影的 token**，全部硬编码（padding 出现 3/4/6/7/8/10/14/16/18/20/24 共 11 种值）
- 仅深色一套主题，未适配 `prefers-color-scheme`
- 强调色单一：`--accent #4c8dff`；语义色 `--ok/--warn/--bad` 用于状态
- 圆角 10 / 8 / 6 / 999 四种；边框统一 `1px var(--line)`；无阴影（除 toast 的 `0 8px 24px`）
- 字号 18 / 14 / 12 / 11.5；等宽字体用于全部技术值（端口、规则、代理命令、日志）
- **对比度实测（WCAG AA）**：`--muted #9aa3b2` on `--panel #171a21` ≈ **6.9:1**；
  primary 按钮 `#08101f` on `#4c8dff` ≈ **5.9:1** —— **均达标，对比度不是当前短板**

## 2. 现存问题

### P0 — 会造成误操作或排查受阻

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| P0-1 | **删除环境无二次确认** | `app.js:174-177`；danger 样式仅 hover 生效（`app.css:96`） | 误点即删；环境绑定端口与规则，恢复成本高 |
| P0-2 | **重分配端口不提示后果** | `app.js:168-173` 仅调用后 `refresh()` | 直接违反 v2 设计的要求："重分配是显式动作并**提示同步客户端配置**"。端口变更后客户端 `export https_proxy=…` 立即失效，用户无从得知 |
| P0-3 | **代理命令不可复制** | `app.js:147` 纯文本 `cell()`；`app.css:82` 在 320px 处 ellipsis 截断 | v2 设计把"工作台给出可直接复制的 `export`"定位为采用率的关键缓解手段，但 UI 只提供被截断的文本 |
| P0-4 | **状态原因只有 `title` 悬浮** | `app.js:142` `healthCell.title = env.health_reason` | `port_conflict` / `config_mismatch` 是需要用户**立即行动**的状态，却只有 hover tooltip；触屏与键盘用户看不到 |
| P0-5 | **状态颜色不足以区分语义** | `app.js:74-81`：`config_mismatch` 与 `port_conflict` 同为 `bad`，`failed` 也是 `bad`，`unhealthy` 为 `warn` | 三种"坏"无法从颜色区分，且仅靠颜色（色觉障碍不可辨）。`config_mismatch` 的根因是 R16「契约下发静默失败」—— 恰恰是最需要被看见的一类 |
| P0-6 | **期望 vs 实际不对比呈现** | 表格分列显示 `health` 与 `desired`（`app.js:141, 146`），原样英文值 | "期望 running 但实际 failed"是最关键的运维信号，当前需要人肉比对两列 |

## 3. 升级目标

### 目标（可度量）

| 目标 | 度量方式 |
|---|---|
| G1 零误操作 | 全部破坏性操作（删除环境 / 删除规则 / 重分配端口）带确认且说明后果 |
| G2 关键资产一键可复制 | `proxy_command` 复制成功率 100%，无需手工选中 |
| G3 状态自解释 | 任一异常状态无需 hover 即可知原因与建议动作；颜色之外至少 2 个通道 |
| G4 API 能力对齐 | UI 覆盖 13/13 端点（含 PATCH 编辑、单环境详情、规则预览） |
| G5 可定位 | ≥ 20 个环境时，定位任一环境 ≤ 3 次交互 |
| G6 窄屏可用 | 720px 宽下全部功能可达，无横向溢出 |
| G7 不改既有约束 | 零构建链、`include_str!` 内嵌、CSP 无 `unsafe-inline`、资产仍为 3 个文件 |

### 非目标（明确不做）

- **不引入前端框架 / 构建链 / WASM** —— 沿用 v2 设计的否决理由：复杂度远大于收益
- **不做多页路由或 SPA 化** —— 保持单文档流，用锚点 + 分区解决导航
- **不做主题切换器** —— P2-6 只是适配 `prefers-color-scheme`，不是加主题选择器
- **不做用户系统 / 多租户** —— v2 设计已定为单机工具
- **不动 CSP 与资产形态** —— `index.html` 内联 `<script>` 计数保持 0

## 4. 改进方向

### D1 语义层：把状态从"颜色"升级为"文本 + 图标 + 建议动作"

为每个 health 值定义固定三元组 `{标签, 视觉, 建议动作}`：

| health | 标签 | 视觉 | 建议动作 |
|---|---|---|---|
| `running` | 运行中 | ok | — |
| `stopped` | 已停止 | 中性 | 启动 |
| `starting` | 启动中 | ok（脉冲） | 等待 |
| `unhealthy` | 不健康 | warn | 查看日志 / 重启 |
| `config_mismatch` | 配置未生效 | bad | 查看契约回显差异 |
| `port_conflict` | 端口冲突 | bad | 重分配端口（并提示同步客户端） |
| `failed` | 启动失败 | bad | 查看日志 |

同时把 `health_reason` 从 `title` 提升为行内可见的次级文本（可展开），
并在 `desired ≠ health` 时显式标注"期望 X / 实际 Y"。

### D2 交互护栏：破坏性操作三级化

| 级别 | 操作 | 交互 |
|---|---|---|
| 一级（可逆、高频） | 启动 / 停止 / 重启 | 直接执行，补 loading 与 disabled 态 |
| 二级（有副作用） | 重分配端口 | 确认框，明确写出"端口将变为 N，客户端 `export https_proxy=…` 需同步更新" |
| 三级（不可逆） | 删除环境 / 删除规则 | 确认框，输入环境名或勾选确认，显示将释放的端口与所绑规则 |

### D3 关键资产：可复制

`proxy_command` 单元格改为「命令（截断显示）+ 复制按钮」，使用 `navigator.clipboard`。
`http://127.0.0.1` 属可信来源（secure context），API 可用；失败时降级为"选中该文本"并 toast 提示。

### D4 信息架构：单页分区 + 轻量导航

- 顶栏下加一条**粘性分区导航**（环境 / 新建 / 对比 / 规则 / 日志），锚点跳转 + 滚动高亮
- 重排面板顺序为任务顺序
  - **激进方案**：规则库 → 新建环境 → 环境表 → 对比 → 日志
  - **折中方案（推荐）**：环境表置顶 + 规则库提到第二位，并在空态里把"先导入规则"做成首屏 CTA
  - 选折中的理由：避免推翻"打开先看环境表"的既有肌肉记忆，同时消解最主要的顺序错配
- 环境行操作收进「⋯」菜单，行内只留 2–3 个高频动作 + 进入详情的入口

### D5 详情视图：从"表格行"到"环境详情"

新增右侧抽屉或展开行，承载当前表格塞不下的信息：

- 完整代理命令（可复制）
- 所绑规则：名字 + 条数 + IP 数 + 内容预览
- 端口与监听地址、期望 / 实际对比、`health_reason` 全文
- 入口：编辑（改名 / 换规则 / 换端口，走 PATCH）、最近日志

这一步同时消化 P1-1 / P1-2 / P1-3 / P1-5。

### D6 规模化与打磨

排序 / 筛选 / 搜索、日志面板增强（跟随 / 暂停 / 过滤 / 下载 / 清空）、对比历史、
token 化 design token、`prefers-color-scheme` 适配、
无障碍修补（`aria-label` / `scope` / `aria-live` / `:focus-visible`）、
顶栏展示监听地址与鉴权状态。

## 5. 功能模块优先级

排序依据：**风险降低 × 使用频率 ÷ 实现成本**。

| 优先级 | 模块 | 对应问题 | 为什么在这个位置 |
|---|---|---|---|
| **P0** | 删除 / 重分配确认框 | P0-1, P0-2 | 唯一会造成不可逆损失的两处；只需一个 Modal 组件即可覆盖 |
| **P0** | 代理命令复制 | P0-3 | v2 设计把可复制性定为采用率的关键缓解；成本极低 |
| **P0** | 状态语义升级（标签 / 图标 / 建议动作 / 原因可见） | P0-4, P0-5, P0-6 | `config_mismatch` 关联 R16「契约静默失败」，看不见就等于规则没生效而用户不知道 |
| **P0** | 端口重分配后的客户端同步提示 | P0-2 | 与 v2 设计"重分配需提示同步客户端配置"的要求直接冲突，属"实现未满足设计"，应优先纠偏 |

## 7. 验收方式（继承 v2 的规矩）

沿用 `docs/acceptance/m3-workbench.md` 的教训 —— **curl 证明不了前端行为**：

  后续回归一律用"在真实元素上派发事件 + 必要时真实键盘激活"，不要依赖坐标点击
- **硬约束不变**：资产 3 文件、`index.html` 内联 `<script>` 计数为 0、CSP 无 `unsafe-inline`

## 8. 风险与已知取舍

| 风险 | 说明 | 缓解 |
|---|---|---|
| 资产文件变大 | 加 Modal / Drawer 后 `app.js` 可能破千行，但仍是单文件 `include_str!` | 设软上限（约 1200 行）；超出则内部拆分为多个外置 `<script src>`（同域，仍满足 CSP） |
| 粘性导航引入定位冲突 | 与现有纵向流叠加，可能出现锚点遮挡 | 用 `scroll-margin-top` 修正，真机验证 |
| 面板顺序调整推翻肌肉记忆 | 用户已习惯"打开先看环境表" | 采用折中方案（环境表置顶），并在 CHANGELOG 记为行为变化 |
| `navigator.clipboard` 可用性 | 依赖 secure context | `127.0.0.1` 已属可信来源；仍保留"选中文本"降级路径 |
| **本次审计未做像素级截图** | 本机无 Playwright / Puppeteer，布局结论由 CSS 推导 | M5-a 开工前补一次真机截图复核，重点看栅格换行点（320px 断点）与表格溢出点 |
