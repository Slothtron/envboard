# 已知限制

这一节**是契约的一部分**，不是免责声明：

- **数据面只实现 HTTP/1.1**。MITM 与直连两侧的 ALPN 都只协商 `http/1.1`（声明 h2 会
  诱导客户端走不支持的协议面）。浏览器正常回退；**强制 h2 的客户端（gRPC 等）会
  失败**。101 升级请求走透传旁路。
- **界面是 Tauri 桌面窗口**：关闭窗口 = 销毁窗口与 WebView、进程常驻；托盘承载回前台
  入口。**开机自启未做**。主题与窗口几何存 `<state_dir>/ui.json`（物理像素；屏外坐标
  只恢复尺寸、不恢复位置）。需要 WebView2 运行时。
- **上游严格档走平台校验器**（rustls-platform-verifier）：Windows 经 Schannel 完整
  口径（当前用户 + 本机 ROOT、AIA 补中间证书、OS 动态根），"哪些域名免名单就能通过"
  随宿主系统信任库而变。某域名要 502 时，把它加进 `insecure_hosts` 或修系统信任库。
- **`insecure_hosts` 是精确域名**：归一化后完全相等才放宽（不做子域继承、不做后缀
  匹配），写入时拒绝通配符。无 SNI 时才退回按上连地址判定。放宽只降校验档，不改写
  SNI。**没有"整个环境全关校验"的开关**。
- **`mitm_hosts` 只解密点名的域名**：名单外的 CONNECT 是盲隧道（不解密、不抓包、
  不改写内容），但**路由照旧**（规则仍改写目标地址），鉴权也仍要在 CONNECT 上判。
- **CA 身份是自己的**：签发链的根是 `envboard`（`envboard-ca-cert.pem`），客户端要
  信任它才能解密流量；CA 与同目录的 `mitmproxy-ca*.pem` 无关。轮换只换证书，不会从
  系统信任库移除旧证书。
- **上游连接不复用**（一问一答）：热改规则/名单不会被连接池里的旧策略穿越。代价是
  被覆盖域名每个请求新建一次上连（多一次 TLS 握手）。正确性优先。
- **请求/响应体默认缓冲**，`max_buffered_body` 上限 8 MiB：超限返回 413/502 而不是
  静默流式。大文件穿透不是当前形态。
- **客户端要改代理配置**（换端口即换环境）—— 工作台给出的 `export https_proxy=…`
  就是为此。
- **PAC / 透明代理 / SOCKS 未做**；上游代理只做 HTTP 形态（CONNECT 隧道 +
  absolute-URI + Basic 鉴权），`https://` 代理、按域名分流、代理链都是写明的非目标。
